# ADR 0002 — Decisiones de las Fases 4 a 6

- Estado: aceptada
- Fecha: 2026-10-16

| # | Decisión | Motivo |
| --- | --- | --- |
| E1 | **Proveedor de IA: Google Gemini** (`gemini-3.6-flash`, configurable con `GEMINI_MODEL`) vía `models.generateContent` con salida JSON por esquema. | Elegido por el usuario: nivel gratuito, visión incluida. La interfaz `AIProvider` (ADR D4) permite cambiar de proveedor escribiendo otro adaptador. |
| E2 | **Sin clave no hay IA simulada en producción**: la función responde `ai_not_configured` y la app lo dice. `AI_PROVIDER=mock` existe solo como modo de desarrollo y la app lo etiqueta "Modo prueba". | Requisito: no presentar datos falsos como reales. |
| E3 | **Las funciones usan siempre la sesión del usuario** (`@supabase/server`, RLS). Nunca `service_role`. La verificación JWT "legacy" de la plataforma va apagada porque el código valida la sesión. | El modelo jamás puede leer o escribir datos de otra persona. |
| E4 | **Cuota diaria por usuario** en la base (`consume_ai_quota`, tabla de solo lectura para el usuario). | Controlar costo y abuso sin servidor extra. |
| E5 | **Fotos de comida:** JPEG reducido a ≤1280 px, carpeta privada `food-photos/<uid>/`, se **borra al terminar el análisis** salvo que el usuario elija conservarla. | Privacidad (requisito 14). |
| E6 | **Calorías desde la base nutricional, no desde la IA**: la IA identifica alimentos y estima gramos con rango y confianza; los macros salen de USDA FoodData Central cuando hay coincidencia. Sin coincidencia se usa la estimación de la IA y se marca "Estimación IA". Todo es editable antes de guardar. | Requisito 8 y ADR D7. |
| E7 | **Rutina base determinista en la app** (reglas por objetivo, experiencia, días, minutos y equipo) + **rutina con IA opcional**. La propuesta de la IA se valida en el servidor (solo ejercicios del catálogo y del equipo disponible, días ≤ 6, series/reps/descanso acotados, recorte por tiempo) y el usuario la revisa antes de guardar. | Funciona sin IA; la IA no puede proponer algo fuera de las reglas. |
| E8 | **Progresión doble** para sugerir peso (mismo peso hasta completar el rango en todas las series, luego +1 / +2,5 kg). Sin historial no se inventa un peso. | "Peso sugerido cuando exista información suficiente". |
| E9 | **Objetivo calórico Mifflin-St Jeor** con límites en la app **y** en la base: mínimo 1200 (mujeres) / 1500 kcal (hombres), déficit ≤ 25 %, superávit ≤ 20 %. Menores de 18: solo mantener. Faltan datos → se piden. | Requisito 9: sin dietas extremas. |
| E10 | **Las acciones del asistente son propuestas** (5 tipos: crear tarea/evento/hábito, reprogramar, completar). Se validan en el servidor contra esquemas y contra los datos del usuario, y **las aplica la app con la sesión del usuario** tras confirmar. | ADR D8; "no permitas operaciones arbitrarias". |
| E11 | **Contexto del asistente según Ajustes → Privacidad** (hábitos, agenda, entrenamiento, nutrición). Las notas nunca se envían. | Requisito 11 y 13. |
| E12 | **XP derivada, no almacenada** (reglas públicas, solo suman). Los logros guardan solo la fecha de desbloqueo. **% de disciplina** = promedio de componentes elegidos por el usuario (hábitos, tareas a tiempo, entrenamiento) en 7 días, sin contar descansos. | Transparente y configurable; nunca castiga el descanso. |
| E13 | **Gráficas propias con `react-native-svg`** (líneas y barras) en lugar de una librería de gráficas. | Ya estaba instalada; sin dependencias nativas nuevas; accesibles y probadas. |
| E14 | **Eventos recurrentes simples** (diario / semanal / mensual, con fin opcional) expandidos en la app conservando la hora local (correcto con horario de verano). Los avisos se programan por repetición. Editar o borrar afecta a toda la serie. | Cubre el uso común sin la complejidad de RRULE. |
| E15 | **Despliegue de funciones sin CLI**: `bundle.sh` genera un archivo por función (`deploy/`) para pegarlo en el editor del panel. | El usuario trabaja en Windows sin CLI de Supabase. |

## Pendiente conocido

- Ilustraciones o videos de los ejercicios: no se incluyeron porque no hay una fuente con licencia verificada; cada ejercicio tiene técnica paso a paso y errores frecuentes redactados para el proyecto.
- Tabla peruana de composición de alimentos (INS/CENAN): el esquema la admite (`source = 'peru_ins'`), pero el catálogo inicial solo trae valores USDA verificables.
- Las funciones no responden CORS (no hace falta para la app Android; sí para una versión web).
- Edición de una sola repetición de un evento recurrente.
